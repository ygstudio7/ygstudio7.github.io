- # 1. 완전 파라미터화 아키텍처 (Fully Parameterizable Architecture)

  본 설계는 모든 하드웨어 구조와 메모리 매핑이 중앙 집중식 패키지(`matmul_pkg`)에서 정의된 파라미터로부터 유도되는
   **"Parameter-First" 설계 철학**을 구현합니다.
   즉, 시스템의 모든 특성은 RTL 수정 없이 파라미터 변경만으로 제어됩니다.

  ------

  ### A. 핵심 하드웨어 파라미터

  - **벡터화된 차원 ($NR, NC$)**
     PE 어레이의 행과 열 개수를 `NR`, `NC` 파라미터로 설정하여
     면적 제약과 목표 처리량에 따라 하드웨어 병렬성을 자유롭게 조절할 수 있습니다.

    - 2×2, 4×4, 8×8 등 자유 확장 가능
    - Generate loop 기반 자동 인스턴스 생성
    - RTL 수정 없이 성능 스케일링 가능

    → 처리량은 **NR × NC에 비례하여 선형적으로 증가**

  ------

  - **데이터 정밀도 ($DW, SW$)**
     입력 데이터(`data_t`)와 누적 결과(`sum_t`)의 비트 폭을
     각각 `DW`, `SW` 파라미터로 관리합니다.
    - INT8 / INT16 / FP16 / FP32 등 다양한 정밀도 지원
    - 로직 수정 없이 정밀도 변경 가능
    - 정확도 ↔ 전력/면적 트레이드오프 조절 가능

  ------

  - **시스템 상한선 (`MAX_IDX`)**
     지원 가능한 최대 행렬 차원을 `MAX_IDX`로 정의하여
     시스템 전체의 스케일을 사전에 규정합니다.

    이를 기반으로 다음 항목들이 자동 설정됩니다.

    - 전체 메모리 용량 (`MAX_DEPTH`)
    - 주소 비트폭 (`AW`)
    - 메모리 주소 지정 범위

    → 대형 행렬 연산에서도 RTL 수정 없이 확장 가능

  ------

  ### B. 지연 시간 인식 동기화 (Latency-Aware Synchronization)

  - **파이프라인 가변성**
     `AB_MEM_LATENCY`, `PE_LATENCY` 파라미터를 통해
     메모리 접근 지연과 연산 파이프라인 깊이를 제어합니다.
    - 실제 SRAM/DRAM 지연 모델 반영 가능
    - 타이밍 요구사항에 따른 파이프라인 깊이 조절
    - 목표 Fmax에 맞춘 구조 최적화 가능

  ------

  - **자동 지연 매칭**
     `pipe_reg` 모듈을 사용하여
     제어 신호와 데이터 경로 간 지연을 자동으로 정렬합니다.
    - 파라미터 변경 시에도 기능 정확성 유지
    - 수동 delay 보정 불필요
    - 파이프라인 변경에도 강인한 구조

  ------

  # 2. 확장성 분석 (Scalability Analysis)

  확장성은 시스템이 증가하는 작업 부하를 처리하거나
   성능 향상을 위해 구조를 얼마나 쉽게 키울 수 있는지를 나타냅니다.

  ------

  ### A. 가속기 아키텍처 및 유연한 행렬 지원

  - **가속기 인터페이스 동작**
     외부 마스터가 입력 데이터를 메모리에 Write한 후 `start` 신호를 인가하면
     연산을 수행하고, 완료 후 `done` 신호를 통해 결과를 회수하는
     전형적인 가속기 모델로 설계되어 시스템 통합이 용이합니다.

  ------

  - **메모리 대체 가능성**
     `matmul_os_top` 모듈 내부에
     입력용 A, B 메모리와 Banked C 메모리를 독립적으로 구현하여
     실제 실리콘 구현 시 표준 SRAM IP로 즉시 대체 가능합니다.

  ------

  - **런타임 타일링(Tiling) 로직**
     하드웨어 고정 크기보다 큰 행렬($M, K, N$)도 처리할 수 있도록
     `cfg_t` 구조체와 타일링 로직(`mt`, `nt`)이 구현되어 있어
     런타임에 다양한 크기의 행렬곱을 지원합니다.

  ------

  - **임의 크기 지원 및 Boundary 처리**
    - `a_addr`, `b_addr` 생성 시
       실제 행렬 크기(`cfg.m`, `cfg.n`)와 비교하여
       유효한 영역만 접근하도록 설계되었습니다.
    - `tile_wb` 모듈에서
       유효 범위 내의 데이터만 Write Enable(`c_we`)을 활성화하여
       결과 메모리에 기록합니다.

  ------

  # 3. 연장성 분석 (Extensibility Analysis)

  연장성은 기존 시스템 동작에 영향을 주지 않고
   새로운 기능을 얼마나 쉽게 추가할 수 있는지를 의미합니다.

  ------

  ### A. 모듈형 하드웨어 설계

  - **PE 레벨 추상화**
     연산 로직이 `pe_os` 모듈에 격리되어 있어
     알고리즘 변경(예: Weight-Stationary) 시
     해당 리프 모듈만 수정하면 전체 시스템에 반영 가능합니다.

  ------

  - **범용 인터페이스 구조**
     `matmul_if`는 `modport`를 통해
     Driver와 Monitor 역할을 명확히 구분하므로
     새로운 신호 및 프로토콜 통합이 용이합니다.

  ------

  ### B. 확장 가능한 UVM 테스트벤치

  본 프로젝트의 검증 환경은
   다양한 시나리오를 즉시 추가할 수 있도록 설계되었습니다.

  - **시퀀스 확장성**
    - Randomized sequence
    - All-ones / Stress pattern
    - Ramp / Diagonal pattern
    - Directed + Random 혼합 회귀 테스트

  ------

  - **범용 컴포넌트 설계**
     Driver, Monitor, Scoreboard는
     임의의 A/B 입력을 처리하도록 일반화되어 설계되었습니다.

  ------

  - **팩토리 오버라이드 지원**
     모든 컴포넌트가 UVM factory에 등록되어 있어
     원본 코드 수정 없이 상속 기반 기능 확장이 가능합니다.

  ------

  ## 5.2 High-Level Block Diagram (Hardware Architecture)

  본 설계의 상위 블록 구성은 **`matmul_os_top`** 을 중심으로,
   (1) 입력 메모리 preload 경로, (2) 코어 연산 경로, (3) Banked C 메모리 저장 및 read-back 경로로 구성됩니다.

  ```
                           +--------------------------------------+
                           |             matmul_os_top            |
                           |                                      |
    Preload A port         |   +------------------------------+   |   Preload B port
    a_we/a_waddr/a_wdata -->|   |   A_mem (model or SRAM IP)   |<--|-- b_we/b_waddr/b_wdata
                           |   +--------------+---------------+   | 
                           |                  | a_rdata[NR]       |
                           |                  v                    |
                           |   +------------------------------+    |
                           |   |                              |    |
    start, cfg ----------->|   |        matmul_os_core         |----|--> done
                           |   |   (FSM: IDLE / TRUN / DONE)   |    |
                           |   |  - tiling/loop control        |    |
                           |   |  - addr gen: a_addr[NR]       |    |
                           |   |             b_addr[NC]        |    |
                           |   +---------------+--------------+    |
                           |                   |                   |
                           |           b_rdata[NC]                  |
                           |                   v                   |
                           |        +----------------------+       |
                           |        |      pe_array_os      |       |
                           |        |   (NR x NC generate)  |       |
                           |        +----------+-----------+       |
                           |                   |                   |
                           |    c_we/c_addr/c_wdata[NR][NC]        |
                           |                   v                   |
                           |   +-------------------------------+   |
                           |   |     C_bank[NR][NC][DEPTH]      |   |
                           |   |  (banked write, per-PE ports)  |   |
                           |   +---------------+---------------+   |
                           |                   |                   |
                           |     bank select + read mux            |
                           |  row_idx/col_idx + c_rd -> c_rdata    |
                           +--------------------------------------+
  ```

  ### 다이어그램 설명(핵심 포인트)

  - **A/B 입력**: 외부 마스터가 preload 포트를 통해 A/B 메모리에 값을 적재한 뒤, `start`와 `cfg(M,K,N)`를 인가합니다.
  - **연산 코어**: `matmul_os_core`가 FSM 기반으로 타일링/루프를 수행하며 `a_addr[NR]`, `b_addr[NC]`를 생성합니다.
  - **PE 어레이**: `pe_array_os`는 `NR×NC`로 확장 가능하며, 병렬 연산 결과를 Banked C 메모리로 기록합니다.
  - **C 저장/읽기**: `C_bank[NR][NC]`에 병렬 write 후, 외부에서는 (row/col index 기반) muxed read로 `c_rdata`를 회수합니다.

  ## 5.3 Detailed Block Diagram (Data/Control Path View)

  아래는 **데이터 경로(Data Path)** 와 **제어 경로(Control Path)** 를 분리해 표현한 버전입니다.

  ```
  [Control Path]
     start + cfg(M,K,N)
             |
             v
   +---------------------+

              |
              | (control signals + optional pipelining via pipe_reg)
              v
  
  [Data Path]
    +------------------+        +------------------+
    |  A_mem (NR read) |        |  B_mem (NC read) |
    +--------+---------+        +---------+--------+
             | a_rdata[NR]                | b_rdata[NC]
             +-------------+  +-----------+
                           v  v
                     +--------------+
                     |  pe_array_os |
                     |  (NR x NC)   |
                     +------+-------+
                            |
                            | c_we/c_addr/c_wdata [NR][NC]
                            v
                   +-------------------+
                   | C_bank[NR][NC]    |
                   +---------+---------+
                             |
                             | row_idx/col_idx + c_rd
                             v
                           c_rdata
  ```

  # 7. RTL Module Descriptions

  본 장에서는 `all.sv`에 구현된 주요 RTL 모듈들의 역할과 설계 의도를 상세히 설명합니다.
   각 모듈은 기능별로 분리되어 있으며, 확장성과 재사용성을 고려한 구조로 설계되었습니다.

  ------

  ## 7.1 `matmul_os_top`

  **역할**
   전체 가속기의 최상위 래퍼(Top-level Wrapper) 모듈로,
   외부 시스템과 DUT 내부 코어 간의 인터페이스를 담당합니다.

  **주요 기능**

  - 외부 마스터로부터 A/B 입력 행렬 preload 처리
    - `a_we`, `a_waddr`, `a_wdata`
    - `b_we`, `b_waddr`, `b_wdata`
  - 내부 A/B 메모리 모델 관리
  - Banked C 메모리 구현 및 read-back mux 제공
  - `matmul_os_core` 인스턴스화 및 신호 연결

  **설계 의도**

  - 실제 실리콘 구현 시
     → 내부 메모리를 **표준 SRAM IP로 바로 대체 가능**
  - 외부 인터페이스와 연산 코어를 분리하여
     → 시스템 통합 및 유지보수 용이

  ------

  ## 7.2 `matmul_os_core`

  **역할**
   가속기의 핵심 제어 블록으로,
   연산 스케줄링 및 주소 생성을 담당합니다.

  **주요 기능**

  - FSM 기반 동작 제어
    - `IDLE → TRUN → DONE`
  - 타일링 기반 반복 제어
    - 타일 인덱스(`mt`, `nt`)
    - 내부 루프(`k` loop)
  - A/B 메모리 주소 생성
    - `a_addr[NR]`
    - `b_addr[NC]`
  - Boundary 체크
    - 실제 행렬 크기(`cfg.m`, `cfg.n`) 기반 유효 영역 판단
  - C bank write 제어 신호 생성
    - `c_we[NR][NC]`
    - `c_addr[NR][NC]`

  **설계 의도**

  - 하드웨어 크기보다 큰 행렬도
     → **런타임 타일링으로 처리 가능**
  - 제어 로직을 단일 모듈에 집중시켜
     → 구조 명확화 및 확장 용이

  ------

  ## 7.3 `pe_array_os`

  **역할**
   `NR × NC` 크기의 PE 배열을 구성하는 모듈입니다.

  **주요 기능**

  - Generate loop 기반 PE 자동 인스턴스화
  - 각 PE에 A/B 데이터 전달
  - 파이프라인 정렬(필요 시 `pipe_reg` 사용)
  - 모든 PE의 결과를 C bank write 포트로 전달

  **설계 의도**

  - `NR`, `NC` 변경만으로
     → PE 어레이 크기 자유 확장
  - 병렬 연산 구조 유지

  ------

  ## 7.4 `pe_os`

  **역할**
   Output-Stationary 방식의 단일 Processing Element(PE)입니다.

  **주요 기능**

  - 입력 A/B 곱셈(Multiply)
  - 누적(Accumulate) 연산 수행
  - 타일 내 K loop 동안 부분합 유지
  - 타일 종료 시 최종 결과 출력

  **설계 의도**

  - 연산 로직을 리프 모듈로 분리
     → 알고리즘 변경 시 영향 범위 최소화
  - 향후 확장 가능
    - Weight-Stationary
    - Input-Stationary
    - Activation (ReLU)
    - Bias add

  ------

  ## 7.5 `tile_wb`

  **역할**
   PE 어레이에서 생성된 결과를
   Banked C 메모리에 저장하기 위한 write-back 정렬 모듈입니다.

  **주요 기능**

  - 타일 좌표(`mt`, `nt`) 기반 주소 계산
  - Boundary 영역에 대한 write masking
  - `c_we` 생성

  **설계 의도**

  - 유효 결과만 메모리에 기록
  - 메모리 오염 방지

  ------

  ## 7.6 `pipe_reg`

  **역할**
   파라미터 기반 파이프라인 레지스터 유틸리티 모듈입니다.

  **주요 기능**

  - 데이터 폭(`DW`) 및
     파이프라인 단계 수(`N`) 파라미터화
  - control/data path 동기화

  **설계 의도**

  - 메모리/연산 지연 모델링
  - 파라미터 변경 시
     → 자동 지연 정렬 유지

  ------

  ## 7.7 `matmul_if`

  **역할**

  # 8. UVM 검증 환경

  

  본 프로젝트의 검증 환경은 **UVM(Universal Verification Methodology)** 기반으로 구축되었으며,
   RTL 설계의 기능적 정확성을 체계적으로 검증할 수 있도록 구조화되어 있습니다.
   특히, 다양한 행렬 크기와 타일 조합, 랜덤 입력 패턴을 효율적으로 검증할 수 있도록
   **확장성과 재사용성을 최우선으로 고려한 구조**로 설계되었습니다.

  

  구성

  - Sequence → stimulus 생성
  - Driver → preload 및 start 제어
  - Monitor → C 메모리 write/read 감시
  - Scoreboard → Golden 비교

  기능

  - 다양한 행렬 크기 테스트
  - partial tile 테스트
  - random / directed 혼합 테스트

  

  ## 8.1 UVM Verification Block Diagram (UVM Architecture)

  검증 환경은 `matmul_if` virtual interface를 기준으로
   Sequence → Driver/Monitor → Scoreboard 흐름으로 구성됩니다.

  ```
                   +----------------------+
                   |      matmul_test     |
                   |  - config + run seq  |
                   +----------+-----------+
                              |
                              v
                   +----------------------+
                   |   matmul_random_seq  |
                   +----------+-----------+
                              |
                              v
  +----------------------+   +----------------------+   +----------------------+
  |     matmul_driver    |   |    matmul_monitor    |   |  matmul_scoreboard   |
  | - preload A/B        |   | - observe C writes   |   | - golden model       |
  | - drive start/cfg    |   | - readback sampling  |   | - compare / report   |
  +----------+-----------+   +----------+-----------+   +----------+-----------+
             |                          |                          ^
             | virtual interface        | virtual interface        |
             v                          v                          |
          +---------------------------------------------------------------+
          |                           matmul_if                           |
          +------------------------------+--------------------------------+
                                         |
                                         v
                                 +---------------+
                                 |      DUT      |
                                 | matmul_os_top |
                                 +---------------+
  ```

  ### 검증 관점 요약

  - **Driver**: A/B preload, `cfg` 설정, `start` 시퀀싱
  - **Monitor**: C bank write 활동과 read-back 데이터를 관측
  - **Scoreboard**: Golden model 기반 결과 비교 및 PASS/FAIL 리포팅

  

  ## 8.2 주요 컴포넌트 설명

  ### 8.2.1 `matmul_test`

  **역할**

  - 전체 검증 시나리오의 시작점
  - 테스트 환경 구성 및 시퀀스 실행 제어

  **주요 기능**

  - 환경(`matmul_env`) 생성
  - 시퀀스 실행 (`matmul_random_seq.start()`)
  - 시뮬레이션 종료 조건 관리

  ------

  ### 8.2.2 `matmul_env`

  **역할**

  - 검증 환경 최상위 컨테이너

  **구성 요소**

  - `matmul_agent`
  - `matmul_scoreboard`

  **기능**

  - 컴포넌트 간 TLM 연결
  - 전역 설정 전달

  ------

  ### 8.2.3 `matmul_agent`

  **역할**

  - DUT와 직접 통신하는 에이전트

  **구성**

  - `matmul_driver`
  - `matmul_monitor`

  **특징**

  - Active agent 형태
  - virtual interface(`matmul_if`) 사용

  ------

  ### 8.2.4 `matmul_driver`

  **역할**

  - DUT 입력 신호 구동

  **주요 기능**

  - A/B 메모리 preload
  - `cfg(M,K,N)` 설정
  - `start` 신호 시퀀싱
  - 타이밍 제어 및 동기화

  **특징**

  - Transaction(`matmul_random_item`) 기반 구동
  - 프로토콜 독립적 구조

  ------

  ### 8.2.5 `matmul_monitor`

  **역할**

  - DUT 출력 관측

  **주요 기능**

  - C bank write 이벤트 감시
  - Read-back 데이터 수집
  - 트랜잭션 형태로 Scoreboard 전달

  ------

  ### 8.2.6 `matmul_scoreboard`

  **역할**

  - Golden model 기반 결과 검증

  **주요 기능**

  - 소프트웨어 reference model 수행
  - DUT 결과와 비교
  - PASS/FAIL 판정

  **특징**

  - 타일 기반 검증 지원
  - Boundary case 자동 처리

  ------

  ## 8.3 시퀀스 구조

  **역할**

  - 반복 테스트 수행

  # 9. 시뮬레이션 동작

  

  본 장에서는 설계된 가속기의 기능적 정확성을 검증하기 위해 수행한
   **시뮬레이션 환경, 실행 방법 및 동작 흐름**을 설명합니다.
   모든 시뮬레이션은 UVM 기반 검증 환경에서 자동 수행되며,
   PASS/FAIL 판정까지 자동화되어 있습니다.

  

  ## 9.3 시뮬레이션 시나리오

  기본적으로 다음 테스트 시나리오가 수행됩니다.

  ### 1) 랜덤 행렬 곱 테스트

  - 랜덤 A/B 행렬 생성
  - 랜덤 `cfg(M, K, N)` 설정
  - 다양한 크기의 행렬 자동 테스트

  ------

  ### 2) Boundary 테스트

  - 하드웨어 크기보다 작은 행렬
  - 하드웨어 크기보다 큰 행렬
  - 부분 타일(Partial tile) 처리 검증

  ------

  ### 3) 스트레스 테스트

  - 최대 크기(`MAX_IDX`) 행렬
  - 연속 반복 실행
  - 장시간 시뮬레이션 안정성 검증

  ------

  ## 9.4 시뮬레이션 동작 흐름

  시뮬레이션 타임라인은 다음과 같습니다.

  1. Reset 인가
  2. A/B 메모리 preload
  3. `cfg(M,K,N)` 설정
  4. `start` 신호 인가
  5. 타일 스트리밍 시작
  6. PE 연산 수행
  7. Banked C 메모리 write
  8. 결과 read-back
  9. Scoreboard 비교
  10. PASS/FAIL 출력

  

  ## 9.5 자동 검증 및 리포트

  - 모든 테스트는 **자동 PASS/FAIL 판정**
  - 실패 시:
    - mismatch 좌표 출력
    - 예상값(Golden) vs DUT 값 비교 로그 출력
  - 성공 시:
    - 테스트 이름과 함께 PASS 로그 출력

  

  ## 9.6 파형(Waveform) 분석

  시뮬레이션 실행 시 다음 신호들을 중점적으로 관찰합니다.

  - FSM 상태 (`IDLE/TRUN/DONE`)
  - `a_addr`, `b_addr` 생성 패턴
  - `a_rdata`, `b_rdata` 타이밍
  - `c_we[NR][NC]` 활성화 구간
  - `c_addr`, `c_wdata` 값 변화

  이를 통해

  - 타일 단위 연산 진행
  - Boundary 처리
  - Banked write 동작

  을 직관적으로 확인할 수 있습니다.

  ------

  ## 9.7 시뮬레이션 결과 요약

  시뮬레이션을 통해 다음 항목을 검증하였습니다.

  - 다양한 행렬 크기에 대한 정확성
  - Boundary 조건 처리 정확성
  - Banked C 메모리 병렬 write 정상 동작
  - 파라미터 변경(NR/NC/DW 등) 시 정상 동작

  

  

  ## 9.8 결론

  시뮬레이션 결과,

  > **모든 테스트 케이스에서 Golden model과 완벽히 일치하는 결과**

  를 확인하였으며,
   설계의 기능적 정확성과 파라미터 변경에 대한 안정성을 입증하였습니다.
